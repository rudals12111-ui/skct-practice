# SKCT 로컬 연습실

PDF 문제집을 문항별 이미지로 잘라 한 문제씩 푸는 개인용 모의시험 앱입니다. SK 공식 앱이 아닙니다.

## 실행

**인터넷 주소(권장):** https://rudals12111-ui.github.io/skct-practice/ 를 PC·아이패드 브라우저에서 엽니다. 설치가 필요 없고, 한 번 연 뒤에는 오프라인으로도 열립니다. 문제집 PDF와 기록은 기기마다 그 브라우저 안에만 저장됩니다.

**원본과 수정:** GitHub 저장소 `rudals12111-ui/skct-practice`가 원본입니다. 저장소에서 파일을 고쳐 커밋하면(저장소 화면에서 `.` 키 → 브라우저용 VS Code) 약 1분 뒤 사이트에 반영되고, 기기에서는 앱을 다시 열 때 새 버전이 적용됩니다. 여러 파일을 한 번에 올릴 때는 `python tools/build_pages.py --source DIR`로 만든 `src.zip.partNN`을 저장소 맨 위에 업로드하면 배포 과정에서 자동으로 풀립니다.

**로컬 실행(선택):**

1. `START.cmd`를 더블클릭합니다.
2. 브라우저에서 `http://127.0.0.1:8787/`이 열립니다.
3. **PDF 문제집 → PDF 불러오기 → ① 문제 쪽 범위 → ② 정답 쪽 범위(선택) → ③ 통합 인식** → 목록 확인 → **시험에 적용** 순서로 진행합니다. 쪽마다 확인하며 자르려면 **자동 인식 (이 쪽) → 인식 결과 추가**를 씁니다.
4. **시험 설정 → 실전 규격 적용 → 설정 적용** 후 **시험 시작**을 누릅니다.

이 PC에 있는 Node.js를 사용합니다. Node가 PATH에 없으면 Codex의 번들 Node 경로도 확인합니다. 앱과 PDF 처리 라이브러리가 포함되어 있어 인터넷 연결이나 `npm install` 없이 실행됩니다. 다른 PC에서는 Node.js 20.16 이상과 최신 Chrome 또는 Edge가 필요합니다.

`dist/index.html`을 직접 더블클릭하는 file:// 실행은 브라우저의 PDF worker·모듈 제한 때문에 지원하지 않습니다. 반드시 START.cmd로 열어 주세요. 서버는 다른 PC에 노출되지 않는 127.0.0.1에서만 실행합니다.

수동 실행: 이 폴더에서 `node server.mjs` 또는 `npm start`.

`'powershell.exe'은(는) 내부 또는 외부 명령...이 아닙니다`가 나오면 PC의 PATH 환경 변수에서 PowerShell 경로가 빠진 것입니다. v1.2.1부터 START.cmd가 PowerShell을 전체 경로로 찾고, PowerShell이 없으면 Node로 서버를 직접 켭니다. 이때는 최소화된 "SKCT server" 창을 닫으면 서버가 꺼집니다.
서버 종료: `STOP.cmd`. 현재 실행기가 시작한 서버만 종료합니다.

## 기능

### v1.2 자동 문항 인식 (OCR)

- 문항 번호(01. 13. 등)를 찾아 번호부터 다음 번호 직전까지를 한 문항으로 자동 자르기
- 스캔 PDF는 이 PC 안에서 한국어+영어 OCR(tesseract.js), 텍스트 PDF는 텍스트 레이어를 바로 사용
- 쪽 머리 제목 상자, 쪽번호·출판사 꼬리말, 오른쪽 색인 탭 자동 제외, ‘기출 키워드’ 꼬리표 가리기
- 한 쪽에 여러 문항, 1단·2단(자동 판별), OCR이 놓친 번호 복구, 번호 건너뜀 경고
- 쪽 머리의 영역명(언어이해 등)으로 영역 자동 지정, [01~02] 묶음은 공통 지문으로 자동 부착
- 첫 문항 위에 남은 본문은 앞 쪽 마지막 문항에 자동 이어 붙이기
- 후보별 제외(✕)·영역 변경 후 추가, 범위 전체 자동 추출(중지 가능, 되돌리기 한 번으로 전체 취소)
- 영역별 준비 문항 수를 실제 시험 기준(20문항)과 비교 표시

### v1.9 수동 보정 후 자동 재배치

- v1.9.1: OCR이 발문 줄을 통째로 놓쳐도 번호 오른쪽의 글자 줄로 문항을 인정(렛유인 2회차 134쪽 11번, 135쪽 15번 누락 해결)

- 목록의 문항마다 번호 칸 추가. 번호·영역을 고치거나 이름 칸에 ‘수열추리 7’처럼 적으면 영역 순·번호 순으로 목록이 바로 재배치(목록 위 **번호순 정렬**로 끄고 켬)
- 영역을 바꾸면 바로 뒤에 이어지는 같은 영역의 연속 번호 문항도 함께 옮길지 확인(OCR이 한 영역 전체를 앞 영역으로 넣었을 때 한 번에 수정)
- 직접 잘라 추가할 때 **번호** 칸에 번호를 넣으면 그 번호로 추가되고 다음 번호로 자동 증가
- 같은 영역·번호가 두 번 나오면 두 번째 회차로 보고 뒤쪽에 따로 배치(두 회차를 한 목록에 넣어도 섞이지 않음). 번호 없는 문항은 원래 앞에 있던 문항 뒤에 유지
- 시험에 적용할 때도 같은 순서로 정리

### v1.8 GitHub 원본 운영

- 저장소에 압축 조각 대신 실제 소스 파일을 두고, 커밋할 때마다 Actions가 `tools/build_pages.py --site`로 오프라인 캐시 목록(sw.js)을 만들어 GitHub Pages에 배포
- 교재 캡처(tests/fixtures), node_modules, 진단 파일은 저장소에서 제외(.gitignore)
- 로컬 주소(127.0.0.1)와 인터넷 주소는 브라우저 저장소가 따로라, 로컬에서 만든 문제집은 ‘문제집 저장’ 파일로 옮기거나 다시 인식

### v1.7 아이패드·오프라인 (GitHub Pages)

- `python tools/build_pages.py` → `build/pages/upload`에 사이트 압축 조각(site.zip.partNN)과 배포 설정(.github/workflows/pages.yml)이 생성됨. GitHub 저장소에 올리고 Settings → Pages → Source를 **GitHub Actions**로 두면 자동 게시
- HTTPS 주소에서 처음 한 번 열면 앱 파일 전체(OCR·PDF 엔진 포함)를 기기에 저장해 이후 오프라인으로 동작. 아이패드 Safari 공유 → **홈 화면에 추가**로 앱처럼 사용
- 게시되는 것은 `dist`의 앱 파일뿐이며 교재·문제·기록은 올라가지 않음. 로컬 START.cmd 실행에는 오프라인 캐시를 쓰지 않음(수정 사항이 바로 반영되도록)
- 터치 기기에서 버튼·계산기·OMR 크기 확대

### v1.6 결과 필터

- 결과 창에서 영역 탭(전체·영역별)과 결과 필터(정답·오답+미응답·오답·미응답·미채점·★ 다시 보기)로 문항 목록을 거름. 영역별 요약 표의 영역 이름을 눌러도 해당 영역만 표시
- **이 목록 복기 시작** 또는 걸러진 목록의 **보기**로 들어가면 이전·다음이 걸러진 문항 사이에서만 이동(예: 오답만 연속 복기)

### v1.5 채점 후 복기

- 결과 창의 **보기**로 문항을 열면 내 답과 정답을 함께 표시(내 답 오답은 빨강, 정답은 초록)
- 문항 번호 바·OMR에 정답/오답/미응답 색, 영역 표시에 영역별 정답 수, 이전·다음으로 영역을 넘어 복기

### v1.4 문제·정답 통합 인식

PDF 문제집 화면에서 **① 문제 쪽 범위 → ② 정답 쪽 범위 → ③ 통합 인식** 순서로 진행하면 문항을 자르고 정답표를 읽어 방금 추출한 문항에 바로 붙입니다.

- 해설이 별도 PDF면 ②에서 **정답이 다른 PDF에 있음**으로 그 PDF를 고릅니다. 문제 PDF는 그대로 유지됩니다.
- 한 쪽에 여러 회차 정답표가 있으면 **정답표 묶음**에서 몇 번째 회차인지 고릅니다. 영역이 다시 나오는 지점에서 회차를 나눕니다.
- 이미 문항을 추출했다면 **정답만 인식해 적용**으로 정답만 다시 붙일 수 있습니다.
- 해설에서 정답표가 영역별 해설 첫 쪽에 흩어져 있어도 괜찮습니다. 정답 쪽 범위를 그 회차 해설 전체로 잡으면 표가 있는 쪽만 골라 읽고, 같은 쪽의 다른 표(참/거짓 표, 자리 배치 표 등)는 동그라미 정답이 없어 제외합니다.
- 결과는 아래 기록에 영역별로 남고, **정답 확인·수정 열기**에서 불확실한 칸을 고칠 수 있습니다.
- 스크린샷 붙여넣기(v1.3)는 그대로 쓸 수 있습니다.

### v1.3 정답표 인식 · 자동 채점

- 해설의 ‘빠른 정답’ 표 캡처를 붙여넣기(Ctrl+V)·이미지 파일·PDF 쪽으로 읽어 영역별 정답 20개를 채움
- 음영 번호 줄과 칸 구분선으로 표를 찾고, 동그라미 정답(①~⑤)은 테두리를 지운 안쪽 숫자를 서체 견본과 비교한 뒤 같은 책의 숫자 모양으로 한 번 더 판별
- 영역명(남색 탭의 흰 글자)을 읽어 영역을 자동 지정, 하나만 못 읽으면 남은 영역으로 추정
- 문제 속 자료 표처럼 동그라미 정답이 없는 표는 무시
- 적용 전 숫자 20자리로 확인·수정, 불확실한 칸 노란색 표시
- 결과 화면에서 바로 재채점(미응답은 오답), 문항 번호가 어긋난 영역은 출제 순서로 매칭

### 시험 화면 (실제 SKCT 구성 반영)

- 실전 규격 프리셋: 5개 영역 × 20문항 × 15분, 이전 문항 복귀 금지, OMR 숨김, 그림판 전체 지우기만
- 문항 번호 이동 바: 앞 문항으로 건너뛰기 가능, 지나간 문항은 실전 설정에서 잠김
- 영역 진행 표시, 결과의 영역별 정답률·풀이 시간·문항당 평균

### 기존 기능


- PDF 이미지 렌더링, 수동 자르기, 전체 쪽 추가, 상하/좌우/2×2 분할, 여러 쪽 일괄 처리
- 텍스트 PDF 문항 번호 기반 분할 후보: 1단·2단 지원, 확인 후 적용
- 공통 지문 붙이기, 여러 쪽을 한 문항으로 이어 붙이기, 문항 이미지 교체
- 문항 순서·영역·정답·이름 편집, 편집 되돌리기, 큰 미리 보기
- 영역별 타이머, 영역 간 안내, 시간 만료 자동 전환·제출
- 실전 모드와 연습 모드, 이전 문항 허용/금지, 선택적 OMR
- 계산기(마우스/키보드), 메모장, 그림판(펜·지우개·굵기·되돌리기)
- 보조 도구 이동·크기 조절과 배치 초기화
- 답안·진행 자동 저장, 문제집 JSON 백업/복원, 정답 입력 채점·결과 CSV

## 자동 인식 사용 팁

- 스캔본은 쪽당 5~9초 정도 걸립니다. 처음 실행할 때 OCR 엔진과 언어 데이터를 읽느라 조금 더 걸립니다.
- 자동 인식은 교재의 문항 번호가 같은 세로선에 정렬되어 있다는 점을 이용합니다. 번호 형식이 특이하거나 인쇄가 흐리면 일부를 놓칠 수 있으니 쪽별 로그의 경고와 목록 미리 보기를 확인하세요.
- 영역명이 쪽 머리에 없는 쪽은 직전에 읽은 영역을 이어서 씁니다. 첫 쪽에 영역명이 없다면 **기본 영역**을 먼저 맞춰 두세요.
- 인쇄된 원본을 이미지로 자르므로 표·수식·그래프가 그대로 보존됩니다. OCR 글자는 영역을 찾는 데만 씁니다.
- 정답표 인식 점검: `node -e "import('./tools/ocr-node.mjs').then(async m=>console.log(JSON.stringify(await m.readKeyFiles(['정답표.png']))))"`
- 개발자 점검: `npm run ocr:check -- 문제집.pdf 41 60 --out=결과폴더` 로 같은 과정을 Node에서 실행해 쪽별 결과와 잘린 이미지를 확인할 수 있습니다.

## 수동 보정

공통 지문을 먼저 선택하고 **공통 지문 지정**을 누르면 이후 문항마다 앞에 붙습니다. 해당 묶음이 끝나면 **공통 지문 해제**를 누르세요. 이어지는 페이지는 오른쪽에서 대상 문항을 선택한 뒤 다음 쪽에서 영역을 드래그하고 **선택 문항에 이어 붙이기**를 누릅니다.

## 시험과 기록

기본 제공 예제 10문항은 조작 확인을 위해 직접 제작한 문제이며 실제 기출·난이도 모사가 아닙니다. 준비된 PDF의 문항 수를 그대로 사용하며 100문항을 자동 생성하지 않습니다. 기본 설정은 5개 영역 각 15분, 영역 사이 안내 60초입니다. 실제 시험은 영역마다 20문항이며, **영역당 출제 문항**을 ‘앞에서부터 20문항’으로 두면 준비한 문항이 더 많아도 20문항만 출제합니다. 추가한 문항이 없는 영역은 제외합니다.

실전 모드는 일시정지를 막고 기본적으로 이전 문항과 OMR을 끕니다. 종료된 영역은 시험 중 다시 열 수 없습니다. 이전 문항 허용 여부는 후기 간 차이가 있어 사용자가 수정할 수 있습니다. 첫 영역은 시작 버튼으로 바로 시작하며, 중간 안내 화면은 실제 예시 문제 대신 영역 정보만 제공합니다.

새로고침·탭 비활성화·창 닫기는 진행 중인 시간을 멈추지 않습니다. 기기 시계를 바꾸지 마세요. 연습 모드에서 **일시정지**를 누른 경우에만 시간이 보존됩니다.

문제집은 브라우저의 IndexedDB에, 진행 상태는 IndexedDB와 localStorage에 저장됩니다. 저장 공간 정리나 브라우저 변경 전 **문제집 내보내기**와 **결과 CSV 저장**을 사용하세요. JSON에는 잘라낸 문제 이미지와 정답이 포함되며 원본 PDF와 응시 결과는 포함되지 않습니다. 원본 PDF를 바꾸어도 기존에 잘라낸 이미지는 남습니다. 같은 주소의 앱은 한 탭에서 사용하세요.

## 조사 자료

앱의 **사용 가이드 → 조사 출처와 화면 재현 가이드라인** 또는 `dist/research.html`에서 공식 안내·응시 후기·공개 연습 도구의 근거와 적용 범위를 확인할 수 있습니다. 공식 시험 화면 원본을 확보하지 못했으므로 픽셀 단위의 동일성을 주장하지 않습니다.

## 개발 및 검증

- 정적 HTML/CSS/JavaScript. 프레임워크 빌드 불필요.
- Mozilla PDF.js 5.4.624. 배포 파일은 `dist/vendor`, 라이선스는 `dist/vendor/PDFJS-LICENSE.txt`.
- tesseract.js 6.0.1(Apache-2.0)과 한국어·영어 best_int 언어 데이터. `dist/vendor/ocr`.
- 자동 인식 로직: `dist/autocrop.js`(순수 함수, Node 테스트), OCR 실행: `dist/ocr.js`.
- 개발 검사: `npm install` 후 `npm test`. 앱 실행에는 패키지 설치가 필요하지 않습니다.
- 자체 제작 PDF 검증 입력: `tests/fixtures/`. `tests/fixtures/user/`는 사용자 교재 4쪽 캡처와 그 OCR 기록으로, 개인 검증용이며 배포 패키지에서 제외합니다.
- 기능별 검증 기록: `QA.md`.


## 300MB 등 큰 문제집에서 1회차만 사용하기

PDF는 최대 1GB까지 선택할 수 있습니다. 예를 들어 300MB 문제집 중 1회차가 PDF 41~60쪽이라면 파일을 선택한 뒤 **시작 쪽 41 / 끝 쪽 60 → 선택 범위 열기**를 누르세요. 책에 인쇄된 쪽번호가 아니라 PDF상의 순서입니다.

선택 범위 안에서만 페이지를 이동하고 문제를 자를 수 있습니다. **여러 쪽을 한 번에 추가** 역시 현재 열어 둔 범위만 처리합니다. 다른 회차를 보려면 범위를 바꾸고 **선택 범위 열기**를 다시 누르세요. 범위를 바꾸어도 이미 추가한 문항은 남습니다.

로컬 File의 필요한 바이트 구간을 PDF.js에 공급하고 자동 전체 선읽기를 끕니다. 파일 전체를 JavaScript ArrayBuffer로 읽거나 원본 사본을 만들지 않습니다. 단, PDF 구조·공유 폰트·이미지·손상 복구 방식에 따라 선택한 쪽 바깥의 데이터도 필요할 수 있으며 메모리 사용량을 일정 수치 이하로 보장하지는 않습니다.

32MB 이하 원본만 브라우저에 저장하며, 더 큰 원본은 이름·크기만 기억합니다. 큰 원본을 새로고침 후 계속 편집하려면 같은 PDF를 다시 선택하고 범위를 열어 주세요. 이미 잘라낸 문항과 시험 기록은 원본과 별개로 계속 보관됩니다. **원본 PDF 닫기**는 원본 연결·캐시를 해제하며 잘라낸 문항을 삭제하지 않습니다.
